## 1. Verdict

This can test whether a frozen playbook improves r2; it does not yet cleanly test match-by-match learning. The biggest weakness is treating one adaptive session—and correlated decisions within it—as independent evidence, then attributing failure to the adviser.

## 2. Over-engineering

- **§2.5 / Phase 3 grading:** defer automatic trust changes. This introduces another learning mechanism before rule injection works.
- **Phase 3 hidden-state lookup:** remove from this experiment. First verify whether one explicit missing field, such as jump phase, resolves ambiguous situations.
- **Phase 1 opponent scan:** start with Ryu; scan others only if Ryu has insufficient headroom.
- **Phase 4 offline scoring:** retain format validation; remove “moves away from moves that led to damage” as evidence of quality. Alternative actions have no recorded outcomes.

## 3. Gaps

- **Twenty pairs is a pilot, not a justified sample size.** Predeclare a worthwhile damage improvement; estimate required pairs from pilot variance. Analyze paired match-level differences with confidence intervals. Existing [`gate()`](https://github.com/beefkknd/laya_vision-vs-SF2/blob/two-system/sf2/rollout.py) uses round-level SE; rounds within matches are clustered, and combined arm SE discards pairing.
- **B’s matches share evolving memory.** A rising curve can reflect opening difficulty/order. Freeze final memory and compare it against empty memory on untouched openings. Repeat reset-memory sessions before claiming reliable online learning.
- **Prevent leakage:** separate development openings from final evaluation. The [journal](https://github.com/beefkknd/laya_vision-vs-SF2/blob/two-system/JOURNAL.md) already acknowledges gate leakage. Retrying revised rules on the same gate compounds it.
- **Opening order is confounded:** existing jitter increases with match index; some damage occurs before scoring starts. Distinct trajectories do not establish independent samples. Explicitly save and randomize opening schedules.
- **C versus B is not adviser isolation:** Claude receives images and human edits; Qwen receives text, operates asynchronously, and changes rules online.
- **Verify Ryu semantics:** projectile RAM, jump/attack states, controllability, round transitions and damage accounting—not merely full starting bars. Existing [`ram.py`](https://github.com/beefkknd/laya_vision-vs-SF2/blob/two-system/sf2/ram.py) documents Dhalsim-specific observations.

## 4. Design flaws

- **Blending already overrides.** For normalized probabilities, `λ > 0.5` guarantees the advised move wins argmax. Your `weight=0.6`, initial-trust example overrides even unanimous opposition. Below that, action selection changes discontinuously; log actual action changes, not just rule hits.
- **Matching is contradictory:** “first match” differs from specificity ranking. Specificity before author means a specific Qwen rule beats a broad human rule. A zero-trust winner could shadow useful rules unless excluded before ranking. [`parse_rule()`](https://github.com/beefkknd/laya_vision-vs-SF2/blob/two-system/sf2/contract.py) accepts arbitrary authors and weight 1; provenance must come from the writer.
- **Grading is confounded:** equal distance/state bins do not equal comparable situations. Overlapping 0.5-second windows reuse damage and include subsequent actions; twenty firings can represent a handful of encounters. Repeated 1-SE checks invite false drops. A match need not even change the action.
- **Round boundaries alone do not ensure reproducibility:** asynchronous arrival changes which memory gets applied. Freeze trust too; record the exact snapshot and activation boundary. Shared four-worker memory destroys a single sequential learning history.
- **Flagging needs temporal definitions:** “round lost” could flag every decision retrospectively. Bound and deduplicate failure episodes; sample audits independently. Define windows in emulator frames: macros last 4, 6 or 24 frames, not uniformly four.

## 5. Sequencing

Verify Ryu’s harness, then test one useful rule and its actual action changes. Only after a frozen playbook improves held-out play should you build autonomous advice and session learning.
